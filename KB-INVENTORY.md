# Knowledge Base Inventory & Staleness Audit (Phase 1)

Audit of the staff app, client portal, and admin against the existing knowledge base
(`packages/db/src/seed-helpers/knowledge-base.ts`, ~100+ system articles across 28
categories). Mapped from current code, not assumptions. Six domain sweeps:
Work/CRM · Scheduling & Documents · Billing & Money · Oversight & Reporting ·
Admin/Security/AI · Client Portal.

**Legend** — **OK** (article matches code) · **STALE** (article exists but code now
differs; the difference is stated) · **GAP** (no article, or feature materially undercovered).

---

## Executive summary

- **Coverage is broad** — most top-level features have an article. The problems are
  (a) a cluster of **stale articles** where this product has moved faster than its docs,
  and (b) a long tail of **newer features with no article**.
- **Highest-harm staleness** (articles that will actively mislead a user):
  1. `client-uploading-documents` tells clients to upload files inside a request or on the
     Files page — **no upload control exists there**. The _only_ place a client can attach a
     file in the entire portal is **Messages**. Clients will hunt for a button that isn't there.
  2. `reporting-overview` states _"there is no PDF export for these reports"_ — the report
     viewer now has a working **⬇ PDF** button.
  3. `appointment-types` lists the wrong seeded set ("Initial Consultation, Tax Preparation…"),
     but **Add default types** actually seeds form names (Individual 1040, 1120-S, 1065, Audit…).
  4. Email-provider docs (`integrations-overview`, `email-not-arriving`) omit **EmailIt**,
     a fully-wired 5th provider.
- **Biggest content gaps:** **Tasks**, **Engagement letters**, the **generic Report Viewer**,
  the staff **Notifications inbox**, the **Alerts** inbox, and a large set of **client-portal**
  features (payment methods/autopay, statement, tax payments, tax-return viewing, updates inbox).
